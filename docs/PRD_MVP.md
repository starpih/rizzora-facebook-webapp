# Rizzora PRD MVP

## 1. 文档目标

本文档定义 Rizzora MVP 阶段的产品结构、核心页面、用户路径和快速实现范围。

本阶段重点验证：

- Facebook 社交账号是否可以作为有效引流入口
- 用户是否愿意从 Facebook 点击进入 Rizzora
- 用户是否愿意与主推虚拟男性角色进行文字和语音聊天
- 免费额度是否能推动注册、登录和付费转化
- 单人物聊天路径是否能形成情感连接和持续互动

## 2. 产品定位

Rizzora 是面向中东、欧洲和北美女性用户的 AI 虚拟男性陪伴产品。

MVP 阶段不做复杂角色市场，而是围绕一个主推男性虚拟人物建立最短转化路径：

```text
Facebook 触达
↓
点击进入 Rizzora
↓
直接与主推人物聊天
↓
体验免费文字 / 语音额度
↓
注册或登录获得更多额度
↓
额度用完后引导付费
```

## 3. MVP 核心目标

### 3.1 业务目标

- 建立 Facebook 到 Rizzora 站内聊天窗口的完整引流路径
- 让用户在最少步骤内开始和主推虚拟人物聊天
- 通过免费额度验证聊天兴趣和语音互动需求
- 通过额度限制验证注册、登录和付费意愿
- 为后续广告投放、内容运营和会员订阅提供数据基础

### 3.2 用户目标

- 用户可以从 Facebook 资料卡片、帖子、Story、Reels 或聊天链接进入 Rizzora
- 用户可以快速看到主推虚拟人物并开始聊天
- 用户可以免费体验一定数量的文字和语音聊天
- 用户可以在额度不足时选择注册、登录、邀请或付费
- 用户可以在注册后保留聊天关系和后续互动机会

## 4. 目标用户

### 4.1 核心用户

- 中东、欧洲和北美的女性用户
- 对情感陪伴、虚拟男友、浪漫语音互动感兴趣的用户
- 通过 Facebook 发现角色内容并愿意点击尝试的用户

### 4.2 用户心理

- 希望获得私密、安全、被关注的情绪陪伴
- 对真实社交有压力，但愿意尝试虚拟互动
- 更容易被人物形象、声音、氛围和第一句对话吸引
- 需要在付费前先获得明确的情感体验价值

## 5. 产品范围

### 5.1 MVP 包含

- Facebook 引流链接
- WebApp 端页面形态
- 单人物落地页
- 单人物聊天窗口
- 文字聊天体验
- 语音聊天入口
- 免费额度计数
- 注册 / 登录弹窗
- 额度用完弹窗
- 订阅引导弹窗
- 基础来源追踪参数

### 5.2 MVP 不包含

- Web 端完整页面形态
- 多人物角色市场
- 复杂角色创建系统
- 真实 AI 语音 API 的完整生产接入
- 真实支付闭环
- 完整多语言系统
- 后台运营系统
- 复杂会员权益体系
- Facebook Messenger 深度机器人集成

## 6. 核心产品结构

MVP 阶段优先支持 WebApp 端页面形态，暂不开发完整 Web 端。

WebApp 是 Facebook 移动流量的核心承接端，承担从点击、开聊、注册、额度耗尽到付费引导的完整闭环。Web 端作为后续扩展，不进入当前 P0 开发范围。

```text
Facebook
↓
Rizzora WebApp
↓
主推人物落地页
↓
单人物聊天窗口
↓
注册 / 登录
↓
额度系统
↓
订阅或聊天包引导
```

### 6.1 外部引流层

入口来源：

- Facebook Profile Bio Link
- Facebook Page CTA
- Facebook Post Link
- Facebook Story Link
- Facebook Reels Link
- Facebook Messenger Auto Reply Link
- Facebook Ads Link

链接格式建议：

```text
https://rizzora.com/m/c/main-character?utm_source=facebook&utm_medium=social&utm_campaign=character_launch&utm_content=profile_card
```

必须记录：

- `utm_source`
- `utm_medium`
- `utm_campaign`
- `utm_content`
- `referrer`
- 首次访问时间
- 是否进入聊天
- 是否注册
- 是否触发付费弹窗

### 6.2 站内承接层

用户从 Facebook 进入后优先进入主推人物落地页或直接进入聊天窗口，而不是进入复杂首页。

页面目标：

- 让用户明确这是一个私密、安全的虚拟陪伴体验
- 让用户快速建立对主推人物的兴趣
- 让用户点击进入聊天

### 6.3 WebApp 端

WebApp 端是移动优先的轻量 App-like 页面形态，主要承接 Facebook 移动流量。

核心作用：

- 让用户从 Facebook 点击后快速进入聊天
- 降低注册前体验门槛
- 强化语音聊天按钮和沉浸感
- 提高首条消息、语音点击、注册和付费转化

MVP 页面：

- WebApp Character Entry
- WebApp Chat
- WebApp Auth Modal
- WebApp Quota Limit Modal
- WebApp Subscription Modal
- WebApp User Center / Profile

### 6.4 聊天体验层

MVP 只提供一个主推虚拟人物。

聊天窗口包含：

- 人物头像
- 人物名称
- 在线状态
- 关系进度
- 消息列表
- 文字输入框
- 语音按钮
- 剩余额度提示
- 额度不足提醒

### 6.5 增长转化层

转化方式：

- 匿名用户免费试聊
- 注册后获得更多免费额度
- 邀请好友获得额外额度
- 额度用完后引导订阅或购买聊天包

## 7. 核心用户路径

### 7.1 主路径

```text
用户在 Facebook 看到人物内容
↓
点击资料卡片或帖子链接
↓
进入主推人物落地页
↓
点击 Start Voice Chat
↓
进入聊天窗口
↓
系统展示人物第一句欢迎语
↓
用户发送文字或语音
↓
消耗免费额度
↓
额度接近用完时提示
↓
额度用完
↓
用户选择注册领取更多额度或付费继续
```

### 7.2 快速路径

适用于广告、Story 和 Messenger 链接：

```text
Facebook 链接
↓
直接进入聊天窗口
↓
人物自动发送第一句欢迎语
↓
用户开始互动
↓
触发注册或付费转化
```

### 7.3 注册路径

```text
匿名用户聊天
↓
额度用完或点击保存聊天
↓
弹出注册 / 登录弹窗
↓
用户完成注册
↓
系统发放注册额度
↓
用户继续聊天
```

### 7.4 付费路径

```text
用户消耗完免费额度
↓
弹出额度用完弹窗
↓
用户点击升级
↓
展示订阅弹窗
↓
用户选择套餐
↓
MVP 阶段进入 mock 支付成功状态
↓
恢复聊天额度
```

## 8. 页面结构

### 8.1 页面形态总览

MVP 只设计和实现 WebApp 端。

WebApp 端页面需要覆盖：

- Facebook 移动端点击后的入口承接
- 单人物聊天
- 登录 / 注册
- 免费额度耗尽提醒
- 订阅引导
- 用户中心 / Profile

### 8.2 WebApp Character Entry

路由：

```text
/m/c/main-character
```

页面目标：

- 移动端优先承接 Facebook 点击
- 首屏建立人物吸引力
- 让用户 1 次点击进入聊天

核心内容：

- 主推人物竖屏视觉
- 人物姓名和在线状态
- 2-3 个角色标签
- 一句强情绪开场文案
- 主按钮：`Start Voice Chat`
- 次按钮：`Text Him`
- 简短隐私提示

交互要求：

- 首屏必须露出主 CTA
- CTA 固定在底部安全区域
- 页面不出现复杂导航
- 不强制注册

### 8.3 WebApp Chat

路由：

```text
/m/chat/main-character
```

页面目标：

- 作为 Facebook 移动流量的核心转化页面
- 提供类 App 的沉浸式聊天体验
- 强化语音按钮和免费额度反馈

核心模块：

- 顶部人物栏：头像、名字、在线状态、返回按钮
- 聊天消息流
- 人物第一句欢迎语
- 底部输入区
- 中央或底部语音按钮
- 剩余额度提示
- 注册 / 订阅触发入口

初始状态：

- 人物自动发送欢迎语
- 输入框可直接使用
- 匿名用户可消耗免费额度
- 用户完成第一轮互动前不弹出强制注册

### 8.4 WebApp Auth Modal

触发条件：

- 匿名免费额度用完
- 用户点击保存聊天
- 用户点击关系进度
- 用户尝试继续语音聊天

弹窗目标：

- 引导用户注册或登录
- 说明注册后可以获得更多聊天机会
- 说明聊天记录和关系进度会被保留

推荐文案方向：

```text
Create your private account to keep this conversation going.
```

注册方式：

- Email
- Google
- Apple
- Facebook Login 后续支持

### 8.5 WebApp Quota Limit Modal

触发条件：

- 免费文字额度用完
- 免费语音额度用完
- 剩余额度低于阈值

弹窗目标：

- 清楚说明额度已用完
- 提供多个继续路径

按钮：

- `Sign up for more free chats`
- `Upgrade to keep talking`
- `Invite a friend`
- `Maybe later`

### 8.6 WebApp Subscription Modal

触发条件：

- 用户点击升级
- 免费额度用完
- 用户主动点击会员入口

页面目标：

- 展示会员价值
- 引导用户订阅或购买聊天包

会员权益：

- 更多文字聊天额度
- 更多语音聊天额度
- 更长语音回复
- 更深关系记忆
- 更亲密的专属互动

MVP 阶段可使用 mock 支付：

- 点击套餐后显示支付成功
- 更新用户额度
- 记录转化事件

### 8.7 WebApp User Center / Profile

路由：

```text
/m/profile
```

页面目标：

- 支持用户查看账号状态
- 支持查看会员状态
- 支持登录、登出和订阅管理

核心内容：

- 用户头像
- 用户昵称
- 当前会员状态
- 订阅 / 管理自动续费入口
- 剩余文字额度
- 剩余语音额度
- 登出入口

MVP 注意事项：

- 未登录用户进入时展示登录引导
- 普通用户展示 `Subscribe Now`
- 会员用户展示 `Manage Subscription`
- 不在 P0 内实现完整账号设置

## 9. 免费额度规则

### 9.1 匿名用户额度

建议默认：

- 文字消息：3-5 条
- 语音消息：1 次

目的：

- 降低首次体验门槛
- 让用户先获得情绪价值
- 在兴趣形成后再触发注册

### 9.2 注册用户额度

建议默认：

- 文字消息：20 条
- 语音消息：5 次

目的：

- 让注册行为有明确收益
- 提高用户愿意登录的概率
- 为后续留存和付费建立基础

### 9.3 邀请奖励

建议默认：

- 每邀请 1 位新用户注册，奖励 10 条文字消息或 3 次语音消息

MVP 阶段可以先展示入口，后续再接入真实邀请追踪。

### 9.4 付费额度

建议先提供两种付费结构：

- 会员订阅
- 一次性聊天包

MVP 阶段优先验证点击和意愿，不强制完成真实支付。

## 10. 关键交互规则

### 10.1 首次进入

- 用户从 Facebook 进入后不强制注册
- 用户可以立即开始聊天
- 系统记录来源参数

### 10.2 聊天中

- 每发送一条文字消息消耗 1 条文字额度
- 每发送或播放一次语音消息消耗 1 次语音额度
- 剩余额度少于 20% 时显示轻提示
- 额度用完后阻止继续发送，并弹出引导

### 10.3 注册后

- 匿名聊天记录合并到注册账号
- 注册成功后发放注册额度
- 用户返回原聊天窗口继续对话

### 10.4 付费后

- mock 支付成功后发放对应额度
- 弹窗关闭
- 用户继续聊天
- 记录支付意向事件

## 13. 验收标准

### 13.1 产品验收

- 用户可以从 Facebook 链接进入 Rizzora
- 用户可以进入 WebApp 端主推人物入口页
- 用户可以从 WebApp 端进入聊天窗口
- 用户可以发送文字消息
- 用户可以点击语音聊天入口
- 系统可以显示并扣减免费额度
- 匿名额度用完后可以触发注册或付费引导
- 注册后可以继续聊天
- mock 付费后可以恢复额度

### 13.2 体验验收

- 首次进入路径不超过 2 次点击即可开始聊天
- WebApp 端首屏必须露出主 CTA
- WebApp 端必须适配移动端安全区域和底部输入操作
- 注册不是首次进入的强制步骤
- 额度提示清晰但不打断早期体验
- 付费引导出现时用户已经体验过聊天价值
- 页面风格符合 romantic dark luxury 方向
- 视觉氛围应私密、安全、女性友好，不 vulgar

### 13.3 数据验收

- 所有 Facebook 来源参数可被记录
- 核心路径事件可被追踪
- 可以记录 WebApp 端访问、聊天、注册、付费意向数据
- 可以区分匿名用户和注册用户行为
- 可以统计从 Facebook 到聊天、注册、付费意向的转化漏斗

## 14. 风险与注意事项

### 14.1 产品风险

- 免费额度太少会导致用户尚未建立兴趣就离开
- 免费额度太多会降低注册和付费动力
- 如果语音体验不够真实，可能影响核心卖点
- 如果一开始强制注册，Facebook 流量转化会显著下降

### 14.2 内容风险

- 人物表达需要浪漫、温柔、有边界
- 避免低俗、过度性暗示或成人直播风格
- 需要强调私密、安全、尊重用户

### 14.3 合规风险

- 需要明确用户数据和聊天隐私说明
- Facebook 广告素材和落地页内容需要避免误导
- 支付前需要清楚说明订阅或额度规则

## 15. MVP 成功标准

MVP 可被视为成功的最低标准：

- Facebook 流量可以稳定进入聊天页
- 超过 50% 的落地页用户点击进入聊天
- 超过 30% 的聊天页用户发送第一条消息
- 超过 15% 的聊天用户点击语音按钮
- 超过 8% 的匿名聊天用户完成注册
- 超过 3% 的额度用完用户点击订阅或聊天包

以上指标为初始验证目标，可根据真实投放成本和用户质量调整。
